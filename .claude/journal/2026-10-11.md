# 2026-10-11

## Services layout and easier setup

- Split into two services: `services/lead-api` (intake, stages, Google sign-in, healthz) and `services/sheets-sync` (worker). Shared code stays in `internal/`. `lead_sync` is the hand-off; the services never call each other.
- Config split into `config.LoadAPI` / `config.LoadSync` with optional settings and defaults: PORT, DB_PORT, LOG_LEVEL, SIGNATURE_TOLERANCE, GOOGLE_REDIRECT_URL (derived from PORT), SYNC_INTERVAL, SYNC_BATCH_SIZE. Tests written first (`internal/config/config_test.go`), which also closes the review's missing-config-test note.
- Migrations take a Postgres advisory lock (goose `WithSessionLocker`) so both services can migrate on start.
- `make setup` (`scripts/setup.sh`): checks tools, creates `.env`, generates secrets, imports `client_secret_*.json`. Idempotent. Verified on a fresh copy: second run left `.env` byte-identical. Temp copy deleted afterwards (it held the client secret).
- Makefile detects Podman or Docker, has `make help`, `up`, `logs`, `ps`, `run-api`, `run-sync`.
- Compose runs db, lead-api, sheets-sync. sheets-sync waits for lead-api to be healthy.
